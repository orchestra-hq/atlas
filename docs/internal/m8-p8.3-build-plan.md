# M8 Phase 3 (P8.3) — fit gating + failure UX

> Build-ready breakdown of **M8 Phase 3** from [m8-build-plan.md](m8-build-plan.md) ("fit gating"), under the ratified [ADR-0015](decisions/0015-bring-any-model-auto-configuration.md). Phases 1–2 built the read-only metadata→`Capabilities` layer ([P8.1](m8-p8.1-build-plan.md)) and the family map + metadata-driven serving ([P8.2](m8-p8.2-build-plan.md)), leaving the `Verdict`'s `Loadable`/`Fits` dimensions reporting `Pending`. Phase 3 supplies those two dimensions — "can the pinned engine load this architecture?" and "does it fit this host's memory?" — and turns a `no` on either into a **clean, actionable, pre-download failure**, so an unsupported architecture or an oversized model fails fast with a useful message instead of a confusing half-broken serve.

## Goal

`atlas inspect <model>` now reports a real `loadable:`/`fits:` verdict (no longer "pending"), and `atlas up --model <repo>` / `atlas run` **refuse before downloading any weights** when (c) the pinned engine version cannot load the model's architecture (an upstream-engine limitation, not an Atlas family-map gap) or when the model will not fit the host's VRAM/RAM — each with a message that says _why_ and _what to do_ (the engine's supported-models page + the one-line PR to extend Atlas's arch list; or the sizing shortfall and the remedy). A loadable, fitting model is unaffected: a known family still serves agent-grade (P8.2), and a loadable-but-unknown family still falls through to today's bare passthrough — the warn-and-serve middle case stays **Phase 4**.

This realizes ADR-0015 Decision 3's three-way verdict: **(a)** known family + loadable + fits → configure & serve (P8.2); **(b)** loadable arch but unknown family → bare today, warn-and-serve in P8.4; **(c)** un-loadable arch _or_ won't fit → the clean failure this phase adds.

## What already exists (seams this phase extends)

- **`internal/modelmeta`** — [modelmeta.go](../../internal/modelmeta/modelmeta.go) owns the normalized `Capabilities` record and the staged `Verdict`, whose `Loadable`/`Fits` fields read `Pending` (set by `verdictFor`). It is a network/parse **leaf** (imports only `catalog`); the family map ([family.go](../../internal/modelmeta/family.go)) keys on **bare engine-name strings** (`"vllm"`, `"sglang"`, `"llamacpp"`, `"mlx"`) precisely so the package needs no `worker` import. Phase 3's arch-support list follows the same convention and lives here.
- **The HF repo listing** — [gguf.go](../../internal/modelmeta/gguf.go:106) `listRepoFiles` reads `…/api/models/<repo>` → `siblings[].rfilename` (names only, no sizes), used to detect/enumerate GGUF quants. Phase 3 extends it to capture **file sizes** (the pre-download size signal), which the safetensors path does not collect today.
- **GGUF header read** — [gguf.go](../../internal/modelmeta/gguf.go) reads the header over a bounded `Range`; a local `.gguf` is read off disk. The selected file's byte size — from the `?blobs=true` listing for a multi-quant repo, the ranged fetch's `Content-Range` total (falling back to `Content-Length` on a non-Range `200`) for a direct URL, or `os.Stat` for a local file — is the GGUF size signal.
- **Scheduler fit math** — [internal/server/scheduler.go](../../internal/server/scheduler.go:164): `kvOverheadFraction = 0.2` and `estimate(model) = Source.Size × (1 + 0.2)` (the weights + KV-cache + activations padding), with `capacityOf(hw) (int64, bool)` summing GPU VRAM (else system RAM). This is the **placement** fit check for the fleet; Phase 3 reuses the same _math_ for the single-node pre-download check. `Source.Size` is populated only for **GGUF catalog** entries today — exactly the pre-download gap this phase fills for raw HF/GGUF specs.
- **Host detection** — [internal/worker/hardware.go](../../internal/worker/hardware.go:17) `Detect() wire.Hardware` (platform + `RAMBytes` + `GPUs[].VRAMBytes`, via `nvidia-smi`/`sysctl`/`/proc/meminfo`). The single-node `up`/`run`/`inspect` host _is_ the local host, so this is the capacity source.
- **Engine version pins** — [internal/runtime](../../internal/runtime): `VLLMVersion = "0.23.0"`, `SGLangVersion = "0.5.10.post1"`, `LlamaCppTag = "b9611"`, `MLXVersion = "0.31.3"`. The arch-support list is maintained against these (ADR-0015 Decision 5) and cites them.
- **Resolution** — [internal/cli/resolve.go](../../internal/cli/resolve.go): `resolveRaw` already inspects a raw spec (best-effort, non-fatal) and auto-configures a known family (P8.2). Phase 3 adds the **gate** here: after a successful inspection, refuse on `loadable=no`/`fits=no` _before_ `worker.Start` (which is where the engine downloads weights). `inspect` presentation is [internal/cli/inspect.go](../../internal/cli/inspect.go) (`presentInspect`, `pendingLine`).

## Decisions taken

### Product (owner) — already settled in ADR-0015

- The three-way verdict and its **default to a clean failure** for an unloadable architecture or an oversized model (Decision 3c) — actionable message, not a half-broken serve. Engine-arch support is keyed to the **pinned engine version** with a **static list + trust-and-catch backstop** (resolved Q1): the static list drives the pre-download verdict; the actual engine load is the final authority that catches a stale list. The warn-and-serve middle case (3b) and any `--require-verified`-style opt-outs are **Phase 4**, not here.

### Technical (lead dev)

- **The arch-support list lives in `internal/modelmeta` (`arch.go`), keyed by bare engine name**, mirroring `family.go`. This keeps "model/engine knowledge" in one leaf package and avoids a `worker`/`runtime` import. It is a positive **allowlist of architectures the pinned engine version can load** (the "engine can load this arch" oracle that Decision 3 needs, decoupled from family): `ArchLoadable(engine string, c Capabilities) (bool, string)` returns whether the arch is loadable and, when not, a short upstream-pointer reason. It is seeded **generously** from each engine's public supported-models list (cited in the file) so a _genuinely_ new/exotic/custom architecture is what trips (c) — not every bring-your-own model. Broadening it is an ordinary conformance-gated PR (ADR-0015 Decision 2), and the file's doc comment names the pinned versions it tracks. The live engine load is the trust-and-catch backstop when the list is optimistic; updating the list is the remedy when it is stale-pessimistic (a `--force`-style override is **deferred**, not needed for the exit criterion).
- **`Loadable` is host-independent; `Fits` is host-dependent and never cached.** `Loadable` depends only on the (binary-pinned) engine version + the model's arch, so `verdictFor` computes it (flipping it from `Pending`). `Fits` depends on _this host's_ free memory, which must not be baked into the `repo@revision` `inspect-cache` (the cache is host-neutral and shared across invocations/hosts). So `verdictFor` leaves `Fits = Pending` in the cached record, and the **consumer computes it live** from local hardware at the point of use (`inspect` for display, `resolveRaw` for the gate). This also keeps a cached pre-P8.3 `Verdict` correct: both dimensions are recomputed from the stable `Capabilities`.
- **Size signal: a new `Capabilities.WeightBytes int64`** — the summed byte size of the model's weight files, captured pre-download: HF safetensors → sum of `*.safetensors` sibling sizes from the repo listing (extended to request sizes via the model API's `?blobs=true`, reading `size`/`lfs.size`); GGUF repo → the **selected** quant file's size; local `.gguf` → `os.Stat`. `0` means "unknown" → the fit check is skipped (best-effort, exactly as the scheduler's `estimate` returns 0 for an unknown size). Non-weight files (tokenizer, configs, `.md`) are excluded.
- **Fit math is shared, not duplicated.** The `0.2` padding and the `size × (1+pad) ≤ capacity` predicate are the scheduler's; Phase 3 lifts the constant to `modelmeta.KVOverheadFraction` and a pure `FitEstimate(c Capabilities) (bytes int64, ok bool)`, and has the scheduler reference the shared constant so the two fit checks cannot drift. (`internal/server` already may import `modelmeta`; the reverse is forbidden and unchanged.)
- **Capacity for the single-node check comes from `worker.Detect()` + `capacityOf`-equivalent.** A small `hostCapacity() (int64, bool)` helper in `internal/cli` calls `worker.Detect()` and sums GPU VRAM (else RAM), behind a package-level seam (`var detectCapacity = …`) so tests inject a capacity without real hardware. `inspect` additionally takes a **`--vram <GiB>` override** (also `--ram`) so a user can ask "will it fit a box with N GB?" for a _target_ host other than the laptop they run `inspect` on — this doubles as the hermetic test seam for the `fits` row. `up`/`run` use the detected local capacity only (the host they serve on _is_ local); no new flag there.
- **The gate fires only on a successful inspection.** If inspection fails (offline, gated, unreadable, or a local safetensors dir we don't inspect), resolution stays on today's bare passthrough — Phase 3 never makes `up` _less_ able to serve than before M8. Inside a successful inspection: `loadable=no` → hard fail; else `fits=no` (when `WeightBytes>0`) → hard fail; else proceed (known family → P8.2 config; unknown family → bare, unchanged).

## Data model

No DB/migration. One additive field on the existing record — `Capabilities.WeightBytes int64` (`json:"weight_bytes,omitempty"`) — which flows through the existing `inspect-cache` JSON; an older cache entry simply omits it (→ unknown → fit skipped), so the schema change is backward-compatible. No new on-disk artifact. The arch-support list and fit math are compiled-in Go.

## Sub-phases

### P8.3a — load/fit signals + verdict (library + `inspect` surface)

**Scope.** The arch-support list, the size signal, the fit math, and their presentation — **no serving/gating change** to `up`/`run`:

- New `internal/modelmeta/arch.go`: the per-engine architecture allowlist (seeded from the engines' supported-models pages, cited; covering the common decoder-only families — Llama, Qwen2/Qwen3, Mistral/Mixtral, Gemma/2/3, Phi/3, GLM, Yi, DeepSeek, Falcon, etc. for vLLM/SGLang; the corresponding GGUF `general.architecture` tokens for llama.cpp; mlx-lm's supported types for MLX), and `ArchLoadable(engine string, c Capabilities) (bool, reason string)` keying on `Architecture`/`ModelType` with the same tolerant normalization the family classifier uses.
- `Capabilities.WeightBytes int64`: extend the HF repo listing to capture sibling sizes (request `?blobs=true`; read `size`/`lfs.size`) and sum the safetensors shards in `inspectHF`; capture the selected GGUF file's size (from the `?blobs=true` listing for a repo, the ranged fetch's `Content-Range` total — `Content-Length` fallback on a non-Range `200` — for a direct URL, `os.Stat` for a local file) in `inspectGGUF`.
- `modelmeta.KVOverheadFraction` (lift the scheduler's `0.2`; have the scheduler reference it) and `FitEstimate(c) (bytes int64, ok bool)`.
- `verdictFor` sets `Verdict.Loadable` to `"yes"`/`"no"` (via `ArchLoadable` for the candidate engine); `Verdict.Fits` stays `Pending` (host-dependent, computed by the consumer).
- `atlas inspect` shows a real `loadable:` (with the reason when `no`) and computes `fits:` live from local hardware (or `--vram`/`--ram` override), no longer "pending (M8 Phase 3)". `--json` carries the live `Fits` and `WeightBytes`.

**API.** No HTTP/openapi change — CLI + library only. New `inspect` flags `--vram`/`--ram` (GiB; override detected capacity for the fit check).

**Acceptance (automated, hermetic — normal `go test` gate).**

- `ArchLoadable` table test: Qwen2/Qwen3/GLM/Llama/Gemma arches → loadable on their candidate engines; a GGUF arch `qwen3` → loadable on `llamacpp`; a fabricated unknown arch (`FooBarForCausalLM` / `model_type: foobar`) → **not** loadable on vLLM, with a non-empty reason; an exotic GGUF arch unknown to llama.cpp → not loadable.
- `FitEstimate`: a `Capabilities` with `WeightBytes = N` → `N × 1.2`, `ok=true`; `WeightBytes = 0` → `ok=false`. Assert `KVOverheadFraction` is the single shared constant (scheduler references it).
- Size capture (httptest): `/api/models/<repo>?blobs=true` serving siblings with sizes → `inspectHF` sets `WeightBytes` = sum of `*.safetensors` shards (ignoring tokenizer/config/`.md`); a single-quant GGUF fixture → `WeightBytes` = the file's size (the ranged fetch's `Content-Range` total).
- `inspect` command test (extending P8.1/P8.2): a supported-arch fixture prints `loadable: yes`; an unsupported-arch fixture prints `loadable: no` with the reason; with `--vram 1` against a multi-GB fixture, `fits: no`, and with `--vram 80`, `fits: yes`; `--json` round-trips `Verdict.Fits` and `Capabilities.WeightBytes`.
- Negative control: remove the unknown arch from the seed list expectation (or point the fixture at a known arch) → `loadable` flips, confirming the row reflects the list and isn't hard-coded.

### P8.3b — fail-fast gating in resolution (serving path)

**Scope.** Turn `loadable=no`/`fits=no` into a clean pre-download refusal in `resolveRaw`, before `worker.Start`:

- After a successful `inspectForResolve`, in `resolveRaw`:
  - **arch gate:** `if ok, reason := modelmeta.ArchLoadable(string(engine), caps); !ok { return error }` — the message names the arch, the engine + pinned version, the engine's supported-models page, and the one-line PR pointer (`internal/modelmeta/arch.go`), distinguishing "likely an upstream-engine limitation" from "if it _is_ supported, add it here."
  - **fit gate:** compute local capacity via `hostCapacity()` (test-seam-injectable); `if est, ok := modelmeta.FitEstimate(caps); ok && est > capacity { return error }` — the message states the estimate (weights + ~20% overhead), the host's VRAM/RAM, the shortfall, and the remedy (free space / larger machine).
- Ordering: `loadable` before `fits` (an unloadable arch is reported as such even on a huge box). The gate runs **only** when inspection succeeded; a failed/skipped inspection (offline, gated, local safetensors dir) stays on the bare passthrough unchanged. A loadable-and-fitting **unknown** family still returns the bare plan (no error, no warning — warn-and-serve is P8.4).
- No new `up`/`run` flag (local host is the serving host); no `--force` override (deferred).

**API.** No HTTP/openapi change. No new flag.

**Acceptance (automated, hermetic).**

- With metadata from an httptest server (`ATLAS_HF_ENDPOINT`) and an injected capacity: `resolveModel(engine=vllm, spec=<unsupported-arch repo>)` returns an **error** naming the arch + upstream link, and (assert) reaches no weight-download path; `resolveModel(engine=vllm, spec=<huge safetensors repo>)` with a small injected capacity errors with the sizing message.
- Regression guards: a loadable + fitting **known-family** spec still resolves to the P8.2 plan (family `engineArgs`, `reasoning`, `ctxHint`, sampling) with no error; a loadable + fitting **unknown-family** spec still returns the bare passthrough (no error, no warning) — proving Phase 3 neither preempts Phase 4 nor regresses Phase 2.
- Best-effort guard: a spec whose metadata fetch 404s → bare passthrough, no gate, no error (unchanged); a successfully-inspected model with `WeightBytes=0` (size unknown) → fit check skipped, proceeds.
- Negative control: revert the arch gate in `resolveRaw` → the unsupported-arch test no longer errors (it proceeds to bare), confirming the test exercises the gate.
- Note: "the refused model genuinely can't serve / the accepted one does" on a real engine is the **Phase-5 conformance** concern; P8.3b's per-PR bar is the resolution-decision assertion above (matching how P8.1/P8.2 deferred end-to-end agent proof).

## Permissions

None new — resolution reaches only public/​user-tokened Hugging Face metadata (the P8.1 token handling, now also the `?blobs=true` listing) and local files; host detection is the existing `worker.Detect` (read-only `nvidia-smi`/`sysctl`/`/proc`). Serving is the existing worker path.

## Risks

- **Arch allowlist too narrow → over-blocks valid models** (defeats "bring any model"). Mitigated by seeding generously from the engines' published supported-arch lists, by `(c)` only firing on a genuine list miss (the common case is a known family → serve, or a loadable-unknown arch → bare/Phase-4 warn), and by the conformance gate + one-line PR extension path. The failure message itself routes the user to add a missing arch.
- **Arch list staleness on an engine-version bump.** Mitigated by the trust-and-catch backstop (the live engine load is the final authority when the list is optimistic) and by the file naming the pinned versions it tracks so a bump prompts a review; the Phase-5 conformance run catches drift.
- **Size signal wrong/absent → bad fit verdict.** HF `?blobs=true` sizes can be missing for non-LFS files or older repos; an absent/zero `WeightBytes` **skips** the fit check (best-effort, never a false refusal). The estimate is an over-approximation (the `0.2` pad is conservative), so the risk skews toward _not_ blocking rather than wrongly blocking.
- **`inspect`-on-a-laptop fit answer misleads for a GPU-box deploy.** Mitigated by the `--vram`/`--ram` override (check a target host) and by `inspect` labelling the fit row against the host it measured.
- **Capacity detection failure** (no `nvidia-smi`, odd platform) → `hostCapacity` falls back to RAM or reports unknown; an unknown capacity skips the gate rather than refusing.

## Deferred (to later M8 phases / follow-ups)

- Unknown-family **warn-and-serve** default + `--require-verified` opt-out + the PR funnel and contributor docs ("add a model family") — **Phase 4**.
- The conformance G-group that auto-configures a catalog-less known-family model and runs the agent tool-use/streaming gates, plus proving a refused model genuinely can't serve — **Phase 5**.
- A `--force`/skip-arch-check override for a stale-pessimistic allowlist (the live-load backstop + a one-line PR cover this for now).
- Inspecting/auto-configuring (and thus gating) a **local safetensors directory** — stays bare passthrough (carried over from P8.2's deferral).
- Per-GPU placement nuance (a model that fits _total_ VRAM but not a _single_ GPU for a non-tensor-parallel serve) — the single-node check uses summed capacity like the scheduler; finer placement stays the scheduler's concern.

## P8.3 review — deferred findings (2026-06-29)

A high-effort review of #128/#129 confirmed nine findings. Seven shipped as a phase-fixes PR (the `--quant` fit-gate weighing the served quant not the default; `sumSafetensorBytes` treating a partial-size listing as unknown; recomputing the verdict from cached `Capabilities` on an inspect-cache hit so a stale `Loadable` can't show; a `Content-Length` fallback for a non-Range `200` GGUF; sharing `server.CapacityOf` so the single-node gate and the fleet placer can't drift on capacity; a test cross-checking `arch.go`'s pinned-version strings against `internal/runtime`; and the `Content-Length`→`Content-Range` doc reconciliation above). Two are parked:

- **Fit/load gate also runs on the fleet-worker load path.** ✅ **Largely resolved** (free-capacity reservation). `gateLoadFit` is reached via `fleetLoader.Load` → `engineRuntime.start` → `resolveModel` → `resolveRaw`, so a worker loading a **raw HF spec** (not a catalog name) arch-/fit-gates it. The `engineRuntime` now tracks **committed** memory (the padded estimate of the models it has launched) and `start()` weighs a new model against **free** capacity (`capacity − committed`), reserving before launch and releasing on stop (so a long-lived worker's accounting tracks load/unload churn). This matches the scheduler's free-capacity placement and also catches a model that won't fit alongside its siblings on single-node `atlas up --model … --model …`. Capacity is captured once at runtime construction (also removing the per-resolve `nvidia-smi` shell-out). **Remaining (still deferred):** the scheduler places **raw** specs blind to size (its `estimate` returns 0 for non-catalog models, so placement skips fit), making the worker the de-facto admission point — it refuses with a `load_failed`, but the scheduler does not size raw specs itself, nor branch on the refusal reason, and there is still no `--force`. Teaching the scheduler to size raw specs from metadata (so placement, not just the worker, is free-capacity-aware) is the remaining fleet-fit work. Linked to the over-block item below.
- **The static arch allowlist will refuse genuinely-loadable architectures whose class name was not transcribed** into `transformersArchs`/`llamacppArchs`/`mlxTypes`. ✅ **Addressed** (`--force` escape hatch + broadened seed). This is the ratified design (ADR-0015 resolved Q1: the static list drives the pre-download verdict, the live engine load is the trust-and-catch backstop) and the gate fires **before** the load, so the backstop cannot otherwise rescue an over-pessimistic miss. Two changes close the gap: (1) `atlas up`/`atlas run` gained **`--force`**, which skips the arch-loadability refusal (with a stderr warning) and lets the engine load be the authority — the user-side trust-and-catch override; the **fit check still applies**, so forcing past the arch list never forces an OOM. (2) the seed lists were broadened from the engines' published supported-model lists (DBRX, Arctic, Solar, Aquila, XVERSE, Persimmon, OPT, GPT-J, MiniCPM3, OLMoE, Mamba2/Jamba/Zamba2, the text-capable Qwen-VL classes, …). Broadening continues as ordinary conformance-gated PRs; `--force` covers the long tail in the meantime. (A `--require-verified`-style _stricter_ opt-out — refuse the warn-and-serve middle case — remains Phase 4.)

# M8 Phase 1 (P8.1) — `atlas inspect`

> Build-ready breakdown of **M8 Phase 1** from [m8-build-plan.md](m8-build-plan.md) ("inspect"), under the ratified [ADR-0015](decisions/0015-bring-any-model-auto-configuration.md). Phase 1 is the read-only metadata→verdict layer: zero behaviour change to `up`/`pull`, independently shippable, the foundation Phases 2–5 build on.

## Goal

A user runs `atlas inspect <hugging-face-repo>` and, **without downloading any weights**, sees the serving plan Atlas would derive from the model's own metadata — candidate engine, context window, chat-template presence, sampling defaults, detected architecture/family name — plus a preliminary verdict ("can this be served, and how"). It is the "will Atlas run this model?" one-shot check. No serving, no resolution change; a clean, low-risk first increment.

## What already exists (seams this phase extends)

- **CLI command tree** — [internal/cli/root.go](../../internal/cli/root.go) registers each `newXCmd()`; commands live one-per-file in `internal/cli/` (cobra, `cmd.Print*` for output, `--state-dir` via `defaultStateDir()` in [up.go](../../internal/cli/up.go:278)). `atlas inspect` is a new sibling.
- **Resolution** — [internal/cli/resolve.go](../../internal/cli/resolve.go) turns a `--model` value into a `resolvedModel`. Phase 1 does **not** change resolution; it adds the metadata/capability layer that Phase 2 will wire into `resolveModel`'s raw-spec branch.
- **Catalog types** — [catalog/catalog.go](../../catalog/catalog.go): `Source` (gguf/hf), `Sampling` (`*float64` temperature/top_p), engine names. The capability record mirrors these shapes so Phase 2 can map family → the same `engine_args`/`Sampling` the catalog uses today.
- **Engine constants** — [internal/worker/worker.go](../../internal/worker/worker.go:28): `EngineLlamaCpp`/`EngineVLLM`/`EngineMLX`/`EngineSGLang`.
- **HTTP-fetch + test idiom** — [internal/store/store.go](../../internal/store/store.go) uses an injectable `*http.Client` (`http.NewRequestWithContext`); [store_test.go](../../internal/store/store_test.go) drives it with `httptest.NewServer` serving fixture bytes. The metadata fetcher follows the same injectable-client + httptest pattern so CI never touches live Hugging Face.

## Decisions taken

### Product (owner) — already settled in ADR-0015

- Command surface is `atlas inspect <model>` (ADR Decision 3); gated/private repos read `HF_TOKEN`/`HUGGING_FACE_HUB_TOKEN` and fail with an actionable 401/403 message; metadata is cached in the state dir keyed by `repo@revision`.

### Technical (lead dev)

- **New package `internal/modelmeta`.** Pure library: fetch + parse + normalize into one `Capabilities` record, with no CLI/serving deps, so Phase 2's `resolveModel` and the Phase-1 command both consume it. The `atlas inspect` command is a thin presenter over it.
- **`Capabilities` is the single normalized record** both metadata paths (HF transformers files in P8.1a; GGUF header in P8.1b) produce: `Format` (safetensors/gguf), `Architecture`, `ModelType`, `ContextWindow` (+ rope-scaling note), `HasChatTemplate`, `Sampling`, and the candidate engine(s) derived from format + host OS.
- **The verdict is staged, and labelled honestly.** Phase 1 cannot give the full three-way verdict: family→agent-config is Phase 2 and the per-engine arch-support list + fit check are Phase 3. So the `Verdict` type is defined now with all three dimensions, but Phase 1 populates only what metadata supports (format/engine/context/template/sampling derived; **family classification and fit/arch-gating explicitly printed as "determined in a later phase"**). This keeps `inspect` truthful rather than implying agent-grade support it can't yet verify.
- **Hermetic tests.** All fetch tests use `httptest` + recorded fixtures (small JSON for HF, a hand-built header for GGUF); no network in CI. A live-HF smoke is opt-in only (env-gated), never in the per-PR gate.
- **No new third-party deps for GGUF** — the header is a small, well-specified binary format; parse the metadata-KV section by hand (P8.1b).

## Data model

No DB/migration. One on-disk artifact: a metadata cache under the state dir, `<state-dir>/inspect-cache/<sanitized-repo>@<revision>.json`, holding the normalized `Capabilities` for a `repo@revision`. Best-effort: a corrupt/missing cache file just triggers a re-fetch.

## Sub-phases

### P8.1a — `atlas inspect` for Hugging Face (safetensors) repos

**Scope.** The `internal/modelmeta` package + the `atlas inspect` command, end-to-end for transformers-style HF repos (the common case):

- Fetch individual small files from `https://huggingface.co/<repo>/resolve/<rev>/<file>` for `config.json`, `tokenizer_config.json`, `generation_config.json` via an injectable `*http.Client`; default `<rev>` = `main`, overridable with `--revision`.
- Auth: send `Authorization: Bearer <token>` when `HF_TOKEN` or `HUGGING_FACE_HUB_TOKEN` is set. On 401/403 return an actionable error ("repo `<x>` is gated or private — set `HF_TOKEN` and accept the license at <https://huggingface.co/><repo>"). On 404 for `config.json`, a clear "not a recognized transformers/GGUF repo" message.
- Normalize into `Capabilities`: `Architecture` (`config.json` → `architectures[0]`), `ModelType` (`model_type`), `ContextWindow` (`max_position_embeddings`, noting `rope_scaling` when present), `HasChatTemplate` (`tokenizer_config.json` → `chat_template` present/non-empty), `Sampling` (`generation_config.json` → `temperature`/`top_p`), candidate engine(s) from format + host OS (safetensors → vLLM/SGLang on Linux, MLX on macOS).
- `atlas inspect <repo> [--revision r] [--json]`: prints the derived plan + the staged verdict (human table by default; `--json` emits `Capabilities`+`Verdict` for scripting). Family + fit/arch dimensions are printed as "pending (Phase 2/3)".
- Metadata cache: write/read `<state-dir>/inspect-cache/<repo>@<rev>.json`; `--no-cache` bypasses; `--state-dir` honored.

**API.** No HTTP/openapi change — CLI-only.

**Acceptance (automated, hermetic).**

- Unit/command test with `httptest` serving fixture `config.json`/`tokenizer_config.json`/`generation_config.json` for a known-family repo (e.g. a Qwen2.5 fixture): `atlas inspect` (with the fetch base URL pointed at the test server) prints the derived architecture, context window, chat-template = present, and the sampling defaults; `--json` round-trips to the expected `Capabilities`.
- A 401 fixture → error names the repo and the `HF_TOKEN` remedy; with the token env set, the request carries the `Authorization` header (asserted on the test server) and succeeds.
- A second `inspect` of the same `repo@rev` serves from the cache (test server records **one** hit, not two); `--no-cache` forces a second hit.
- Negative control: with `chat_template` removed from the fixture, `HasChatTemplate` flips to false and the output reflects it.

### P8.1b — `atlas inspect` for GGUF repos

**Scope.** Extend `internal/modelmeta` + `atlas inspect` to GGUF-format repos/files without downloading weights:

- Detect a GGUF target (repo whose resolve listing/target is a `.gguf` file, or a direct `.gguf` URL/path) and read **only the header** via an HTTP `Range` request (the GGUF metadata-KV block sits at the file start) — grow the range if the KV section exceeds the first read. A local `.gguf` path reads the header off disk.
- Parse the GGUF header: magic/version, then the metadata KV store; extract `general.architecture` and the embedded `tokenizer.chat_template` (when present). Normalize into the **same** `Capabilities` (`Format=gguf`, engine candidate = llama.cpp, context window from the arch's `*.context_length` key when present).
- Multi-quant GGUF repos: Phase 1 (inspect) reports the quant files it sees and which the default heuristic (prefer `Q4_K_M`, else nearest) would pick, noting `--quant` will override at serve time (Phase 2). Inspect itself does not download.

**API.** No HTTP/openapi change — CLI-only.

**Acceptance (automated, hermetic).**

- A `httptest` server serving a hand-built minimal GGUF header (magic + a few KV pairs incl. `general.architecture` and `tokenizer.chat_template`) over `Range` requests: `atlas inspect` prints `Format=gguf`, the architecture, context window, and chat-template = present, and the server records that **only a bounded byte range** was requested (no full-file GET) — the "inspect before download" guarantee.
- A multi-quant fixture (listing several `*.gguf` files) → output lists them and names the `Q4_K_M` default; a header missing `chat_template` → `HasChatTemplate=false`.
- Negative control: corrupt the magic bytes → a clear "not a valid GGUF file" error, not a panic.

## Permissions

None — `atlas inspect` is read-only, unauthenticated locally, and reaches only public/​user-tokened Hugging Face metadata.

## Risks

- **HF metadata shape drift** (field names, nesting). Mitigated by tolerant parsing (absent fields → "unknown", never a crash) and fixtures pinned from real repos.
- **GGUF header size variance** (large embedded templates can push the KV block past a first fixed range). Mitigated by the grow-the-range loop with a sane cap.
- **Network flakiness / live-HF coupling.** Mitigated by hermetic httptest in the per-PR gate; live HF only behind an opt-in env smoke.

## Deferred (to later M8 phases)

- Family → agent-config map (tool-call/reasoning parser, template quirks) and wiring metadata-driven resolution into `resolveModel` — **Phase 2**.
- Per-engine-version arch-support list + VRAM/RAM fit pre-check (the authoritative "engine can/can't load" and "won't fit" verdict dimensions) — **Phase 3**.
- Warn-and-serve / `--require-verified` middle-case behaviour and the PR funnel — **Phase 4**.
- The conformance gate auto-configuring a catalog-less HF model — **Phase 5**.

## Phase-1 review — deferred findings (2026-06-28)

High-effort review of #117/#118 found one crash bug and several smaller issues. The crash and the cheap correctness/UX fixes shipped as a phase-fixes PR (GGUF length-overflow hardening, collision-safe cache key, `--no-cache` refresh semantics, single-file `File:` line, GGUF revision consistency, owner-only cache perms). These were judged not worth their cost now and are parked:

- **Stale cache for the moving `main` ref.** Metadata is cached by `repo@revision`; for the default `main` (a moving ref) there is no TTL/invalidation, so a re-tagged `main` serves stale capabilities until `--no-cache`. Consider a short TTL or skipping the cache for moving refs.
- **`.gguf`-suffix targets that aren't a local file or URL** (e.g. a `repo/file.gguf` form) error out instead of resolving against HF; the message guides the user, but the in-repo-file case could be handled.
- **Partially-gated repos**: a 401/403 on the optional `tokenizer_config.json`/`generation_config.json` aborts inspection rather than degrading (only `config.json` should be fatal).
- **No URL escaping**: a slashed revision (e.g. `feature/x`) or special characters build a wrong resolve URL rather than erroring.
- **Connection reuse**: 404/error response bodies aren't drained before close, so the three sequential metadata fetches don't reuse a keep-alive connection (perf only).
- **`chat_template` as a list of objects** reports present on any non-empty list without checking the entries carry a non-empty template.
- **`context_length` encoded as a non-32/64-bit int** is dropped (reported as unknown); and sampling floats print via `%g` (scientific notation / dropped `.0`). Both very low impact.
